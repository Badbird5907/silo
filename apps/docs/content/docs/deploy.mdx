---
title: Deploying Silo
description: Deploy the complete Silo stack to Cloudflare with Alchemy.
---

Silo deploys entirely to Cloudflare. The root `alchemy.run.ts` file provisions the OpenNext applications, ingest Worker, R2, Durable Objects, Queues, Hyperdrive, cron triggers, and domains.

## Prerequisites

- Node.js and pnpm versions from the root `package.json`
- a PostgreSQL database reachable by Cloudflare Hyperdrive
- a Cloudflare account and API token
- application, ingest, and docs domains in Cloudflare DNS

## Configure

Copy `.env.example` to `.env.local`. For deployment, provide Cloudflare credentials, `ALCHEMY_PASSWORD`, database URLs, the three domains/URLs, and the authentication/signing secrets described in the repository migration runbook.

## Local development

```bash
pnpm install
pnpm db:migrate
pnpm dev
```

Alchemy runs local versions of the Cloudflare bindings. PostgreSQL is the only Docker dependency; Silo no longer needs local Redis or MinIO.

## Deploy a stage

```bash
pnpm infra:deploy -- --stage staging
```

For the first production deployment, leave `ATTACH_PRODUCTION_DOMAINS` unset so the Workers can be tested at their `workers.dev` URLs. Set it to `true` only during the planned domain cutover.

```bash
ATTACH_PRODUCTION_DOMAINS=true pnpm infra:deploy -- --stage production
```

Run database migrations separately before application traffic is moved:

```bash
pnpm db:migrate
```

The full production drain, verification, rollback, and Vercel decommission procedure is in `docs/migrations/vercel-to-cloudflare.md` in the repository.
